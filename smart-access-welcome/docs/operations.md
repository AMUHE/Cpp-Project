# 运维手册

## 启动检查

1. 确认配置文件只允许服务账户和管理员修改。
2. 确认级联模型、Qt 插件、OpenCV DLL 和 SQLite 驱动存在。
3. 启动终端，访问 `/health/live` 和 `/health/ready`。
4. 打开摄像头并确认 `camera=ready`；完成首次录入后确认 `recognizer=ready`。
5. 执行一次测试身份验证，核对语音、欢迎页、模拟门锁和数据库事件。

## 健康状态

- `live=ok`：进程事件循环可响应。
- `ready=ok`：必需组件可用；语音关闭属于配置状态。
- `ready=degraded`：至少一个组件不可用或模型尚未生成。

语音属于非关键组件，失败时仍可运行；摄像头、识别器、数据库或真实门锁失败时，生产部署必须拒绝放行并告警。

## 常见故障

| 现象 | 检查 |
|---|---|
| 未找到人脸检测模型 | 设置 `SAW_CASCADE_PATH` 或部署到 `cascades/` |
| 摄像头打不开 | 索引、架构、占用进程、DirectShow 驱动和隐私权限 |
| 无法识别 | 是否完成录入、阈值、光照、模型/标签是否成对存在 |
| 语音不可用 | Windows 语音包、SAPI 服务、Qt texttospeech 插件和音频设备 |
| 数据库不可用 | 数据目录权限、磁盘空间、SQLite 插件、WAL 文件锁 |
| 8080 端口占用 | 修改 `server.httpPort`，确认没有残留终端进程 |
| 浏览器不更新 | WebSocket `/ws`、代理升级头、浏览器控制台和系统时间 |

## 数据维护

- 每日监控数据库大小、磁盘剩余空间和拒绝事件异常增长。
- 由应用启动清理超过保留期的事件；长期停机设备需额外计划任务补偿。
- 删除人员时必须同步删除样本并重新训练模型；当前版本没有网络管理接口，应由受控本地流程执行。
- 禁止直接编辑 `labels.csv` 或部分复制模型文件。

## 日志

应用在数据目录的 `logs/application.jsonl` 写入逐行 JSON 日志，单文件达到 5 MiB 后轮转，保留 5 个历史文件。字段包括时间、级别、类别和经过长度限制的消息。日志不得记录人脸图像、模型内容、令牌或完整网络请求；应由文件 ACL 限制读取，并纳入磁盘与异常级别监控。

## 事故响应

发现误放行、数据库篡改或人脸数据泄漏时：立即断开真实门锁适配器并切换人工流程；保全配置、数据库和系统日志；撤销受影响模板；按组织安全与隐私流程通知；完成原因分析后才能恢复。不要通过公开 Issue 上传生物特征或门禁记录。

## 回滚

保留上一版本完整程序目录、配置 schema 和数据库备份。回滚前停止进程；若新版本执行过不可逆数据库迁移，必须先运行对应降级脚本或恢复备份。恢复后重新执行健康和测试身份验证。
