# 测试策略

## 测试分层

1. **领域单元测试**：连续匹配、冷却、拒绝优先和无效配置。
2. **基础设施测试**：JSON 配置、SQLite 往返、模拟门锁自动复位。
3. **协议集成测试**：HTTP 状态码、健康接口、安全头和 WebSocket 初始快照。
4. **组件测试**：使用合成人脸/许可夹具测试图像归一化和模型加载。
5. **硬件验收**：摄像头断连、遮挡、门锁反馈和断电恢复，仅在受控实验环境执行。
6. **端到端验收**：录入—连续识别—策略—开门—语音—欢迎页—审计全链路。

## 自动化测试

CMake：

```powershell
cmake --preset windows-debug
cmake --build --preset windows-debug
ctest --preset windows-debug --output-on-failure
```

遗留 qmake 工具链可使用：

```powershell
.\scripts\run-tests.ps1 -QtRoot E:\Qt\5.14.2\mingw73_32 `
  -MingwRoot E:\Qt\Tools\mingw730_32
```

测试不得包含真实人员图像、姓名、凭据或生产日志。图像测试夹具应为合成数据或具有明确许可且不可关联真实员工的数据。

## 门禁验收场景

| 场景 | 预期结果 |
|---|---|
| 同一已知身份连续三次 | 仅第三次产生一次放行事件 |
| 冷却期内继续匹配 | 不重复开门、不重复播报 |
| 已知与未知交替 | 连续计数重置，不放行 |
| 未知连续三次 | 拒绝、不请求门锁、写审计 |
| 数据库不可用 | 健康降级；生产策略应配置为拒绝优先 |
| 语音引擎不可用 | 视觉/门锁/审计继续，健康降级 |
| 摄像头断线 | 停止决策、状态离线、门保持锁定 |
| WebSocket 断线 | 浏览器退避重连并重新获取快照 |

## 发布门禁

- 所有自动测试通过，编译器警告为零。
- Release 包在干净 Windows 虚拟机启动。
- `/health/live` 为 `ok`；摄像头、识别、数据库为 `ready` 后才允许现场验收。
- 人工验证中文语音、音量和姓名隐私策略。
- 完成数据库备份恢复、配置回滚和断电恢复演练。
