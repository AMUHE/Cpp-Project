# Qt 终端 UI 设计交付说明

## 1. 设计任务

交付目标不是一张静态效果图，而是一份可被 Qt Designer/Qt Creator 继续编辑、可直接参与编译、具备完整运行状态的工程 UI。主文件为：

```text
apps/terminal/main_window.ui
```

文件只使用 Qt Widgets 标准组件和布局，不依赖 QML、WebView、外部字体、图片或设计工具导出的绝对坐标代码。

## 2. 用户与关键任务

### 值守人员

需要快速确认摄像头、识别模型、审计库和语音服务是否正常，并能在少量操作内启动识别或录入人员。

### 运维人员

需要明确设备索引、接入模式、服务端口和故障状态，避免把“进程在线”误判为“门禁可用”。

### 被识别人员

主要关注摄像头方向、验证进度以及允许/拒绝反馈，不应看到复杂配置和相似身份数据。

## 3. 信息架构

```text
MainWindow
├─ Top Bar
│  ├─ 产品名称
│  ├─ 系统时间
│  └─ HTTP 服务状态
├─ Live Vision Card
│  ├─ 当前门禁状态
│  ├─ 摄像头实时画面
│  └─ 摄像头 / 模型 / 数据库 / 语音指标
└─ Control Sidebar
   ├─ 单摄像头/双目模式与设备索引
   └─ 启动 / 停止 / 录入 / 识别动作
```

视觉画面占主要空间，控制区保持单列，避免操作按钮覆盖视频。正式运行页面只保留状态、字段名称和操作文字，不承载工作流程教程、隐私声明或技术背景；这些说明统一放在开发、部署和安全文档中。高风险“停止”按钮与主操作使用不同颜色，但不使用过度警告的纯红大面积背景。

## 4. 视觉系统

### 色彩令牌

| 令牌 | 色值 | 用途 |
|---|---|---|
| Canvas | `#07111F` | 应用背景 |
| Surface | `#0B1828` | 卡片和顶栏 |
| Surface Raised | `#0E2032` | 表单、指标 |
| Border | `#17304A` | 默认分隔 |
| Primary | `#5ED8FF` | 主操作、品牌强调 |
| Success | `#64E6AF` | 在线、通过 |
| Warning | `#FFD27A` | 录入、拒绝、降级 |
| Text Primary | `#E8F1F8` | 主要文字 |
| Text Muted | `#7690A6` | 时间等次要信息 |

### 字体层级

- 产品标题：18 px / Bold
- 区域标题：18 px / Bold
- 正文与控件：14 px
- 标签和状态：11–12 px
- 默认字体：Microsoft YaHei UI；缺失时由 Qt 使用系统回退字体

### 间距和圆角

- 页面边距：24 px
- 卡片内边距：18–20 px
- 模块间距：14–18 px
- 控件高度：40–48 px
- 卡片圆角：16–18 px
- 控件圆角：10–12 px

## 5. 组件状态

| 组件 | 初始 | 活跃 | 成功 | 警告/异常 |
|---|---|---|---|---|
| `mainStateBadge` | 等待设备 | 身份验证中 | 设备在线/验证通过 | 录入中、验证未通过、流异常 |
| `serviceStatusLabel` | 启动中 | — | 本地服务端口 | 服务异常 |
| `cameraStatusValue` | 离线 | 在线 | 在线 | 由主状态显示异常 |
| `recognizerStatusValue` | 未就绪 | 等待录入 | 模型就绪 | 检测器缺失 |
| `databaseStatusValue` | 检查中 | — | SQLite 就绪 | 不可用；禁止开门 |
| `speechStatusValue` | 初始化 | — | 中文引擎就绪 | 不可用或已关闭 |

按钮启用规则仍由业务层控制：摄像头未启动时不能录入或识别；模型未就绪时不能开始识别；打开设备后不能修改设备索引。

接入方式默认选择“单摄像头（电脑内置或外接）”。只有“两台独立摄像头”模式启用第二摄像头索引；普通 USB 摄像头通过主索引选择，不需要双目设备。

## 6. Qt Designer 编辑方法

1. 使用 Qt Creator 打开项目后，在项目树双击 `apps/terminal/main_window.ui`；或在 Qt Designer 中直接打开该文件。
2. 页面结构全部由 `QVBoxLayout`、`QHBoxLayout` 和 stretch 控制。不要点击“打破布局”后用绝对坐标摆放。
3. 全局视觉样式位于 `MainWindow.styleSheet` 属性，可在 Designer 的“改变样式表”编辑器中修改。
4. 组件通过动态属性实现语义样式，例如 `role=status`、`status=ready`、`role=metricValue`。
5. 修改文字、边距或颜色不会影响业务；修改下列 `objectName` 前必须同步 C++：

| 不可随意改名 | 业务用途 |
|---|---|
| `videoLabel` | 摄像头画面 |
| `modeComboBox` | 摄像头接入模式 |
| `primarySpinBox` / `secondarySpinBox` | 设备索引 |
| `openButton` / `closeButton` | 摄像头生命周期 |
| `enrollButton` | 人脸录入 |
| `recognizeButton` | 识别启停 |
| `mainStateBadge` | 主流程状态 |
| 四个 `*StatusValue` | 组件健康摘要 |

## 7. 自适应策略

- 设计基准：1440 × 900。
- 最小窗口：1180 × 760。
- 主内容宽度比例为 7:3，实时画面优先获得额外空间。
- 视频保持原始宽高比，空白区域由深色预览容器吸收。
- 右侧控制保持单列，不随宽度变化重排按钮，避免触摸和鼠标操作位置漂移。
- 控制卡下方留白用于保持操作区靠上，不再填充教程或说明卡片。
- 如需适配 1024 px 以下屏幕，应新增紧凑版 `.ui` 或滚动容器，而不是继续压缩当前触控尺寸。

## 8. 可访问性与现场使用

- 状态不只依赖颜色，同时提供中文文本和圆点符号。
- Tab 顺序按“模式 → 索引 → 启动 → 停止 → 录入 → 识别”定义。
- 主按钮最小高度 42 px，核心识别按钮为 48 px。
- 深色主题针对室内门禁屏减少眩光；实际部署仍需在目标显示器上检查对比度和亮度。
- 语音是视觉反馈的补充，不作为唯一状态通道。

## 9. 设计验收清单

- `.ui` 能被目标 Qt 版本的 `uic` 无错误解析。
- Qt Designer 预览中无控件重叠、裁切或脱离布局。
- 1180 × 760 与 1440 × 900 下主要任务均可见。
- 无摄像头、无模型、数据库异常和语音异常均有明确文本状态。
- 放行、拒绝、录入和识别中状态可区分。
- 所有操作按钮与现有 C++ 信号连接保持有效。
- 正式运行页面不存在英文眉题、操作教程或大段解释文字。
- 样式不依赖外部文件、网络资源或开发机绝对路径。
