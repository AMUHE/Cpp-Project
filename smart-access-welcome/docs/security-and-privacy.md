# 安全与隐私设计

## 数据分类

| 数据 | 分类 | 默认处理 |
|---|---|---|
| 人脸样本、特征模板 | 高敏感生物特征 | 本地受限存储，不提交、不上传 |
| 姓名、人员编号 | 个人信息 | 最少采集，按授权展示 |
| 门禁事件 | 敏感业务数据 | 审计留存，按期限删除 |
| 运行日志 | 内部数据 | 脱敏、滚动、限制访问 |
| 配置和密钥 | 机密 | 配置与密钥分离，不入 Git |

## 强制控制

- 默认只监听回环地址，所有失败和不确定状态均拒绝开门。
- 管理操作需要认证、授权和审计。
- 数据目录使用操作系统 ACL，发布程序目录只读。
- SQL 使用参数化查询，网络和配置输入进行长度、范围和枚举校验。
- 放行前先持久化审计意图；数据库不可用时不执行门锁动作。
- 语音是非授权辅助通道，在独立线程运行；故障不得改变门禁决定。
- 日志不输出原始图像、特征模板、认证令牌或完整请求体。
- 密钥通过操作系统凭据存储或部署系统注入。
- 依赖锁定版本，并生成第三方许可证和软件物料清单。

## 生物特征生命周期

1. 录入前说明用途、保存期限和删除方式，并获得适用法律要求的授权。
2. 只采集满足质量要求的最少样本。
3. 样本与人员业务数据使用不可推断的 ID 关联。
4. 禁用人员立即停止通行；删除时清除样本、模板和后续模型中的身份。
5. 到期数据自动删除，并产生不含原始数据的审计事件。

## 活体检测

现有双摄代码不等同于活体检测。`livenessRequired=false` 仅适用于研发演示。生产环境必须接入经过评估的活体模块；模块超时、不可用或不确定时拒绝通行。

## 开源发布检查

- Git 历史不得包含人脸、数据库、模型、日志、令牌和私钥。
- 文档与构建配置不得包含开发机绝对路径或用户名。
- 测试素材必须是已授权公开素材、合成数据或程序生成内容。
- 核验第三方模型、Qt、OpenCV 和 Web 依赖许可证。
- GitHub Actions 使用最小权限和固定大版本。
